# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SCOPE Studio turns a founder's brand brief into a **6-pillar brand strategy** (mission, vision,
persona, values, voice/tone, promise) that is generated by AI, edited on an interactive canvas, and
refined through an AI copilot chat. It is a two-process app:

- **Frontend** — TanStack Start + React 19 + Vite + Tailwind v4 (`src/`), talks to the backend over HTTP.
- **Backend** — FastAPI + LangGraph + DSPy (`backend/app/`), served on `:8000`, Postgres for storage,
  **OpenRouter** as the LLM gateway (not the Anthropic API directly). Local development runs the API
  and Postgres as Docker containers inside WSL 2.

The frontend hardcodes the backend at `http://localhost:8000` (`src/lib/api.ts`).

## Commands

Frontend (uses **bun**; `package-lock.json` also present):
- `bun run dev` — Vite dev server (frontend only).
- `bun run build` — production build (also the main typecheck/build gate).
- `bun run lint` — ESLint. `bun run format` — Prettier.
- `bun run dev:full` / `bun run scope` — bash wrappers around `scripts/scope-dev.sh` for the WSL 2
  workflow: start Docker Compose services for api/db, then start Vite.

Backend (from `backend/`, Python 3.11):
- `pip install -r requirements.txt`
- `uvicorn app.main:app --reload --port 8000`
- Full stack incl. Postgres: `docker compose up` from WSL 2 (api container on `:8000`, db container on
  `:5432`).
- Requires `backend/.env` with at least `OPENROUTER_API_KEY` (see `app/core/config.py` for all settings;
  `OPENAI_API_KEY`/`OPENAI_API_BASE` are accepted aliases). Tables auto-create on startup (dev convenience).

There is **no test suite** in the repo today.

## Architecture & data flow

The product is a linear pipeline; each stage persists to Postgres keyed by `session_id`:

1. **Brief intake** (`/api/brief/analyze`, route `src/routes/identity.tsx` → backend `api/brief.py`)
   takes text + reference images. The heavy lifting is in `agents/prompt_pipeline.py`, a **DSPy** chain:
   `EnhanceBriefPrompt → GenerateMarketingBrief → EvaluateBriefQuality` (auto-retries once if the
   evaluator fails). Region-aware (`usa` / `mena` / `gcc`, normalized in `normalize_region`).
2. **Approve brief** (`/api/brief/approve`) unlocks the canvas.
3. **Canvas** (`src/routes/canvas.tsx`) renders the pillars as a radial orbital timeline
   (`components/ui/radial-orbital-timeline`, plus `components/scope/BrandGraph3D.tsx` using three.js /
   react-three-fiber). Canvas state lives in `components/scope/CanvasContext.tsx` (`useCanvas`).
4. **Copilot chat** (`components/scope/CopilotChat.tsx` → `/api/chat` → `agents/brand_agent.py`) is a
   **LangGraph** agent: `prepare_context → chatbot → (tool_handler) → END`. Its only tool,
   `create_brand_node`, proposes pillar revisions that the frontend reconciles back onto the active node.
5. Downstream: **marketing analysis** (`/api/marketing`), **logo concept** (`/api/logo`), **export**.

Backend layout is conventional FastAPI: `api/` (routers) · `agents/` (LLM logic) · `schemas/` (Pydantic
I/O) · `db/models.py` · `core/` (config, database, security/JWT). `main.py` is an entry point only.

## Prompt system — read before touching `backend/app/agents/`

This is the most fragile part of the codebase. All system prompts live in
**`backend/app/agents/prompts/__init__.py`** (`SYSTEM_PROMPT_1..17` plus the route-facing
`BRAND_ARCHITECT_PROMPT`, `MARKETING_SYSTEM_PROMPT`, `LOGO_SYSTEM_PROMPT`, `BRIEF_SYSTEM_PROMPT`). When
editing prompt text:

- **Preserve every `{placeholder}` token** — `prompt_pipeline.py` and the routes `.format()` / inject them.
- **Keep the "Respond ONLY with raw JSON, no markdown" rules verbatim** where present — routes parse the
  model output as JSON, and the exact key names in those JSON blocks are the API contract (mirrored by the
  TypeScript types in `src/lib/api.ts`). Do not rename keys.
- `brand_agent.py` depends on the `create_brand_node` tool being called **six times** on approval, and on
  the `[AUTO-GENERATE]` shortcut prefix. Don't change that behavior when rewording the prompt.
- There is an explicit **anti-slop directive** (a banned-buzzword list, e.g. "delve", "leverage",
  "synergy") in `BRAND_ARCHITECT_PROMPT`. Extend it; don't weaken it.

## Frontend conventions

- Path alias `@/` → `src/` (`vite-tsconfig-paths`). UI is shadcn-style primitives in
  `src/components/ui/`; app-specific composites in `src/components/scope/`.
- Routes are **file-based** (`src/routes/*.tsx`); `routeTree.gen.ts` is generated — don't hand-edit it.
- The copilot UI is **bilingual (en/ar)** with full RTL support: copy lives in the `T` and `CHOICES`
  tables in `CopilotChat.tsx`, and `dir="rtl"` flips layout. Keep both languages in sync when changing copy.
- Chat mode (`free` / `guided`) persists to `localStorage` (`scope_chat_mode`); auth token is
  `scope_token`. Styling is Tailwind v4 with CSS custom props (`--scope-purple`, `--gradient-brand`, etc.)
  defined in `src/styles.css`.

# Orchestration rules
- Opus plans, reviews, and authors prompts. Codex (MCP tool `codex`) implements.
- Always Plan Mode first. Delegate implementation to `codex` with a full spec. Review the diff.
- Only hand-edit small glue. Use `codex-reply` to correct Codex instead of rewriting.
- Run lint + typecheck + tests after each task. Report results.
- Arabic-first product: every user-facing surface must support RTL and Arabic typography.
